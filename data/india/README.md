# India Healthcare Resilience Dataset — Master Documentation

## 1. Dataset Overview

This dataset serves as the foundational data layer for the **India Healthcare Resilience Platform** (BRICS Hack2Skill Track 3: *Smart Health & Supply Chain Resilience*).

It provides a research-grounded, representative India-wide primary healthcare network combined with 365-day synthetic operational telemetry. The platform enables ML demand forecasting, anomaly detection, stockout risk estimation, and safe resource redistribution simulation.

> [!IMPORTANT]
> **Primary Rule: Never Confuse Real Data with Simulated Data.**
> Every record and field explicitly declares its provenance category. Public healthcare directory references are preserved, while daily operational telemetry (demand, inventory, footfall) is synthetically simulated under strict mathematical constraints.

## 4. Provenance System

All data elements follow strict provenance definitions:

1. **`REAL`**: Verified real-world facility facts from authoritative source materials (e.g. initial 8 reference facilities).
2. **`REAL_REFERENCE`**: Public healthcare reference facts or official guidelines used for context.
3. **`ESTIMATED_SUPPORTED`**: Facility characteristics estimated from city population density and health infrastructure norms.
4. **`REFERENCE_STANDARD`**: Standard clinical guidelines, IPHS staffing standards, or essential medicine catalogue definitions.
5. **`DERIVED`**: Values calculated deterministically from source data (e.g. Haversine distance, travel time heuristics).
6. **`SIMULATED`**: Synthetic daily operational time-series generated under bounded mathematical rules.
7. **`ML_OUTPUT`**: Outputs produced by machine learning models (demand forecasts, anomaly z-scores, stockout risk).
8. **`LOGIC_OUTPUT`**: Outputs generated by deterministic decision rules (transferable surplus, alert triggers).
9. **`COUNTERFACTUAL_SIMULATION`**: Replay trajectory reflecting state evolution under system intervention.

## 6. Inventory Conservation Equation

Daily inventory evolution strictly adheres to the physical conservation law:

$$\text{closing\_stock}_t = \text{opening\_stock}_t + \text{received\_units}_t + \text{incoming\_transfers}_t - \text{outgoing\_transfers}_t - \text{consumed\_units}_t$$

Where:
* $\text{consumed\_units}_t = \min(\text{opening\_stock}_t + \text{received\_units}_t, \text{demand\_units}_t)$
* $\text{unmet\_demand}_t = \text{demand\_units}_t - \text{consumed\_units}_t$
* Negative stock is strictly prohibited ($\text{closing\_stock}_t \ge 0$).

## 7. Machine Learning Join & Preprocessing Strategy

ML models should NOT read JSON files directly during feature extraction. Instead, execute a modular join using canonical keys:

$$\text{phc\_id} + \text{medicine\_id} + \text{date}$$

```text
phcs.json (Static Facility Features)
       +
medicines.json (Static Resource Features)
       +
demand.csv (Historical Demand Telemetry)
       +
inventory.csv (Stock Telemetry)
       +
staff_attendance.csv (Operational Capability Telemetry)
       ↓
Preprocessed ML Feature DataFrame
```
